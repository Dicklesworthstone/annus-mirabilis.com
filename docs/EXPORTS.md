# Machine-Readable Exports (`/exports/v1/`)

Documentation and contract specification for machine-readable exports generated by Annus Mirabilis (`annus-mirabilis.com`).

---

## 1. Overview & Purpose

Annus Mirabilis publishes machine-readable exports under the `/exports/v1/` route. These exports allow automated indexers, academic archives, AI coding and research agents, and computational linguists to fetch precise, structured data representations of Einstein's 1905 papers, their sentence-level bilingual alignments, equations, argument reconstructions, and experiment parameters without scraping HTML.

All exports are static files served with standard MIME types and precomputed cryptographic checksums.

---

## 2. Stability Guarantees

1. **Versioned Namespace:** All exports in this version are anchored at `/exports/v1/`.
2. **Additive Evolution:** Any additions to `v1` schemas (new optional fields, additional metadata) will be strictly backward-compatible.
3. **Breaking Changes:** Any breaking schema modification (field removals, type changes, path renaming) requires a new major version prefix (e.g., `/exports/v2/`). An existing version is **never** silently rewritten with incompatible semantics.
4. **Byte Determinism:** Compiling identical content inputs under the same release profile produces byte-identical files and identical SHA-256 digests.

## 3. Endpoint Structure

All paths are relative to the site root:

| Endpoint Path | Format | Content / Purpose |
|---|---|---|
| `/exports/v1/index.json` | JSON | Master inventory of all exports with paths, byte sizes, SHA-256 digests, and version identities. |
| `/exports/v1/papers/<slug>.json` | JSON | Complete paper record: metadata, chronology, journal citation, section outline, rights statements, and discovery links. |
| `/exports/v1/papers/<slug>/<section>.json` | JSON | Section-level export: sentence-level bilingual parallel texts, source blocks, readings, footnotes, and editorial notes. |
| `/exports/v1/papers/<slug>/<section>.md` | Markdown | Safe plain-text Markdown export of the section with escaped HTML characters and LaTeX mathematics. |
| `/exports/v1/equations/<id>.json` | JSON | Modern and historical LaTeX, spoken text, quantity bindings, and derivation references. |
| `/exports/v1/arguments/<id>.json` | JSON | Analytical argument graph: premises, evidence, conclusion, limitations, and the four meanings. |
| `/exports/v1/experiments/<id>.json` | JSON | Declarative experiment manifest: parameters, units, defaults, and historical basis (zero executable code). |
| `/exports/v1/tei/<slug>.xml` | XML | TEI P5 XML critical edition with `<teiHeader>` and bilingual parallel `<s>` sentences. |
| `/exports/v1/jsonld/<slug>.json` | JSON-LD | Schema.org `ScholarlyArticle` structured data for bibliographic indexers. |
| `/exports/v1/corpus/<slug>.tsv` | TSV | Sentence-aligned bilingual parallel corpus (`id \t german \t english`) for NLP and translation research. |

## 4. The Master Index (`/exports/v1/index.json`)

The master index allows indexers and agents to verify and fetch only changed files.

### Schema:
```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "ExportIndex",
  "type": "object",
  "required": ["schemaVersion", "contentRevision", "releaseProfile", "files"],
  "properties": {
    "schemaVersion": { "const": 1 },
    "contentRevision": { "type": "string" },
    "releaseProfile": { "type": "string" },
    "files": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["path", "bytes", "sha256", "schemaVersion", "contentRevision", "format", "mimeType", "description"],
        "properties": {
          "path": { "type": "string" },
          "bytes": { "type": "integer", "minimum": 0 },
          "sha256": { "type": "string", "pattern": "^[a-f0-9]{64}$" },
          "schemaVersion": { "const": 1 },
          "contentRevision": { "type": "string" },
          "format": { "enum": ["json", "markdown", "xml", "tsv"] },
          "mimeType": { "type": "string" },
          "description": { "type": "string" }
        }
      }
    }
  }
}
```

## 6. Publication Mirror & Release Profiles

Exports faithfully reflect the published website state according to the active release profile:

- **`preview` Profile:**
  - Includes draft units and machine-draft translations.
  - Drafts are explicitly marked with `draft: true` and their corresponding `reviewState` (e.g., `"machine-draft"` or `"draft"`).
- **`production` / `launch` Profiles:**
  - Only published, verified units are exported.
  - Unreleased sections or machine drafts are completely excluded from both exported files and `index.json`.

---

## 7. Safety & Structural Integrity

1. **No Executable Code:** Exports contain strictly static, declarative data. No executable JavaScript, TypeScript, WebAssembly, or solver code is emitted.
2. **No Reader-Private State:** Reader notes, tours, bookmarks, and simulation histories reside exclusively in local browser storage and are never exported.
3. **Escaped Markdown Source Text:** Characters in historical German text and translations that could be misinterpreted as HTML tags or Markdown structures (`<`, `>`, `*`, `_`, `[`, `]`, `` ` ``) are escaped with backslashes (e.g., `\<` and `\*`). Markdown exports contain zero rendered HTML tags.
4. **Mathematical Formulas:** Formulas in Markdown are presented as raw LaTeX delimited by `$$` with authored spoken text beneath:
   ```markdown
   $$
   E = m c^2
   $$

   E equals m c squared
   ```
