# Returnable Brownian reading preview

The site now has an executable reading path, not only isolated laboratories.
`/papers/brownian-motion/` contains six explanatory passages; `/s4/` and `/s5/`
under that route provide section-only readings. `/foundations/` and its twelve
lesson routes supply finite prerequisite paths and worked examples. The homepage,
paper catalogue, discovery encounter and all three Brownian labs link into it.

These are **original, AI-assisted draft explanations in modern notation**. They
are not a German transcription, an English translation, a reviewed critical
edition, or a complete source inventory. The source-status faces deliberately
say that German, English, gloss, alignment and facsimile remain in preparation.
No source-review signoff or broader bead closure is implied.

## Read, ask, investigate, return

Each passage has an overview, a full explanation and an expanded derivation.
Modern qualifications are a separate switch, not a fourth position on the detail
control. Native per-passage derivation disclosures work without JavaScript and
retain their open state when global detail changes. All formula HTML and MathML
is generated by KaTeX on the server; no client-side math parser is introduced.

“Why?”, “Show the missing step” and “Show me one example first” open registered
foundation lessons. Further prerequisites stay in a bounded twelve-frame
clarification stack. Back, Forward, Escape, Back one step and Return to the exact
step restore the reading context and focus. Direct `?open=foundation:<id>` links
admit one registered lesson, not a serialized private stack. A face change that
hides the original inline trigger returns focus to the same passage instead.

The embedded BM-01 tracer laboratory stays mounted through in-page detail,
face and clarification changes. Opening a lesson creates no random draws or
worker; applying trial settings explicitly starts the existing host worker.
The accepted run identity, snapshot version, draw count and results are retained.
This does **not** promise worker persistence through a full route navigation or
reload; a general route-placement lifetime registry remains separate work.

The prepaint script and hydration parser share the three numeric detail values,
`overview/full/steps` aliases, input-size limit and `am:settings:v1:detail` storage
key. Valid explicit detail overrides stored preference. Storage failure does not
block reading. Changing detail replaces history instead of adding another Back
step. Passage-copy links include only the public reading axes and stable anchor;
clipboard denial reveals a selectable field. Notes and trial settings are not
copied into passage links.

## Authoring and compilation

`content/` admits four closed JSON record kinds for this preview: paper outline,
argument, foundation and citation. The loader rejects malformed/duplicate-key
JSON, non-NFC text, symlinks, unsafe math commands, unsupported fields and paths,
and file/count/total-size budget violations. The compiler resolves references,
checks placement identities and prerequisite cycles, and emits explicit pending
review diagnostics. This is not yet the plan's complete YAML/Markdown content
compiler or the source/translation/equation-AST schema inventory.

`prepare:content` runs before dev, build, typecheck and reference tests. Generated
paper and foundation payloads carry hashes and byte counts. Their public URL
namespace includes both authored-input and compiler-source digests, so a compiler
change cannot silently reuse old immutable URLs. The manifest is published last;
a rejected compile leaves the previous complete manifest untouched but fails the
build command. Readable Markdown and structured JSON exports share these versioned
URLs. Old generated directories are not deleted automatically.

## Run and verify

```sh
npm install --ignore-scripts --no-audit --no-fund
npm run dev
# Open /papers/brownian-motion/

npm run test:reference
npm run typecheck
npm run build
npx playwright install --with-deps chromium
npm run test:browser
```

The preview workflow uses Node 22.16.0, not the separately ratified Node/Bun
combination. `scripts/test-reader-browser.mjs` exercises the production static
export, real embedded tracer worker, no-JavaScript reading, prepaint behavior,
clarification returns, source-status honesty, copied-link privacy, JSON/Markdown
exports, static lesson routes, 320-pixel reflow, print reading and automated
accessibility. Screenshot and structured-check artifacts are retained by the
existing workflow. A particular run's results apply to its exact commit only.

Manual screen-reader and disabled-reader review, Firefox/WebKit and real-device
verification remain outstanding. So do reviewed source alignment, complete
historical fixtures, semantic equations, the general source-aware return system,
notebook/control tapes, audited FrankenSim/WASM conformance and publication gates.
The reader connects implemented preview functionality; it does not deploy the
site or declare the Brownian reference-slice acceptance gate complete.
